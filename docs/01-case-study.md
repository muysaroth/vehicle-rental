# ផ្នែកទី ១ · ការវិភាគករណីសិក្សាអាជីវកម្ម (Business Case Study Analysis)

> **សំណួរ៖** «ក្រុមហ៊ុនជួលយានយន្តមួយ ជួបការលំបាកក្នុងការតាមដានការកក់ — តើ MIS អាចជួយកែលម្អបានដូចម្តេច?»

## ១. ព័ត៌មានក្រុមហ៊ុន (ក្រុមហ៊ុនសម្មតិ)

| | |
|---|---|
| **ឈ្មោះ** | Mekong Wheels Co., Ltd. |
| **ទីតាំង** | ភ្នំពេញ (ការិយាល័យ + ចំណតឡាន ១ កន្លែង) |
| **អាជីវកម្ម** | ជួលយានយន្ត (ប្រចាំថ្ងៃ) និងលក់យានយន្តមួយទឹក/ថ្មី |
| **យានយន្តជួល** | ៣៧ គ្រឿង — ឡានតូច ១០, SUV ៧, វ៉ាន់ ៤, ភីកអាប់ ៤, ម៉ូតូ ១២ |
| **យានយន្តសម្រាប់លក់** | ២២ គ្រឿង ក្នុងឆ្នាំ (លក់បាន ១៨) |

| **អតិថិជន** | ~៨៤ នាក់ (ក្នុងនោះ ៦ ជាក្រុមហ៊ុន៖ ទេសចរណ៍, ដឹកជញ្ជូន, រៀបចំកម្មវិធី, NGO) |
| **ទំហំប្រតិបត្តិការ** | ~១,៩០០ ការជួល/ឆ្នាំ · ចំណូលជួល ~$៣៣៧,០០០/ឆ្នាំ |

## ២. ស្ថានភាពមុនមាន MIS (As-Is)

ក្រុមហ៊ុនប្រើ **សៀវភៅកក់ក្រដាស + Excel ដាច់ៗ + Telegram/ទូរស័ព្ទ**៖

- អតិថិជនទូរស័ព្ទ ឬផ្ញើសារ Telegram → បុគ្គលិកបើកសៀវភៅមើលថាឡានទំនេរឬអត់
- កត់ការកក់ក្នុងសៀវភៅ (ឈ្មោះ, ឡាន, ថ្ងៃ) — ប្រាក់កក់កត់លើក្រដាសវិក្កយបត្រ
- ពេលប្រគល់/ទទួលឡាន កត់គីឡូម៉ែត្រលើក្រដាសដាច់ដោយឡែក
- គណនេយ្យករវាយបញ្ចូល Excel ម្តងទៀតនៅចុងខែ
- ការលក់ឡាន និងការបង់រំលស់ តាមដានក្នុង Excel មួយទៀត
- ចំណាយជួសជុល/ធានារ៉ាប់រង នៅក្នុងវិក្កយបត្រក្រដាស

## ៣. ការកំណត់ប្រព័ន្ធព័ត៌មាន (Identify current information systems)

| ប្រភេទប្រព័ន្ធ | តួនាទី | **មុន** (As-Is) | **ក្រោយ** (ប្រព័ន្ធថ្មី) |
|---|---|---|---|
| **TPS** — Transaction Processing System | កត់ត្រាប្រតិបត្តិការប្រចាំថ្ងៃ | សៀវភៅកក់, វិក្កយបត្រក្រដាស | ម៉ូឌុល **ការជួល** (កក់ → ប្រគល់ → ទទួលវិញ → បង់ប្រាក់), **ការលក់**, **ចំណាយ**, **អតិថិជន** |
| **MIS** — Management Information System | របាយការណ៍សង្ខេបជាប្រចាំ សម្រាប់អ្នកគ្រប់គ្រងកម្រិតកណ្តាល | Excel ចុងខែ (យឺត ១–២ សប្តាហ៍) | **ផ្ទាំងគ្រប់គ្រង (Dashboard)** — ឡានកំពុងជួល, ហួសកំណត់, ត្រូវប្រគល់/ទទួលថ្ងៃនេះ, ចំណូលខែនេះ, ប្រាក់ជំពាក់ |
| **DSS** — Decision Support System | ជួយសម្រេចចិត្តដែលមិនមែនជាទម្លាប់ | គ្មាន — សម្រេចតាមអារម្មណ៍ | **របាយការណ៍ & ការសម្រេចចិត្ត** — ROI, អត្រាប្រើប្រាស់, ពិន្ទុវិនិយោគ តាមប្រភេទឡាន, និន្នាការប្រចាំខែ, Excel what-if |
| **ESS** — Executive Support System | ទិដ្ឋភាពរួមសម្រាប់ម្ចាស់ | គ្មាន | KPI សង្ខេបលើ Dashboard + ឯកសារ Excel Dashboard |
| **OAS** — Office Automation | ទំនាក់ទំនង/ឯកសារ | Telegram, ទូរស័ព្ទ | (នៅប្រើ) + នាំចេញ Excel ពីប្រព័ន្ធ |

## ៤. ការវិភាគបញ្ហា (Analyze problems)

| # | បញ្ហា | ឫសគល់ | ផលប៉ះពាល់ |
|---|---|---|---|
| P1 | **កក់ជាន់គ្នា (double booking)** — ឡានមួយកក់ឲ្យអតិថិជន ២ នាក់ថ្ងៃតែមួយ | គ្មានការត្រួតពិនិត្យស្វ័យប្រវត្តិ, សៀវភៅមួយក្បាល បុគ្គលិក ២ នាក់ | បាត់បង់អតិថិជន, ខូចកេរ្តិ៍ឈ្មោះ |
| P2 | **ឆ្លើយយឺត** «មានឡានទំនេរទេ?» ចំណាយ ៥–១០ នាទី | ត្រូវរកមើលសៀវភៅ និងសួរគ្នា | អតិថិជនទៅក្រុមហ៊ុនផ្សេង |
| P3 | **មិនដឹងថាឡានណាហួសកំណត់** | គ្មានការរំលឹក | បាត់ចំណូលពិន័យ, ការកក់បន្ទាប់ត្រូវពន្យារ |
| P4 | **ប្រាក់ជំពាក់មិនច្បាស់** (ប្រាក់កក់, រំលស់) | ប្រាក់កត់នៅកន្លែងច្រើន | ខាតប្រាក់, ជម្លោះជាមួយអតិថិជន |
| P5 | **ទិន្នន័យដដែលៗវាយច្រើនដង** (សៀវភៅ → Excel) | គ្មានប្រព័ន្ធកណ្តាល | កំហុស, ចំណាយពេល ~២ថ្ងៃ/ខែ |
| P6 | **របាយការណ៍យឺត ហើយមិនពេញលេញ** | Excel ចុងខែ, គ្មានថ្លៃចំណាយតាមឡាន | អ្នកគ្រប់គ្រងមិនឃើញបញ្ហាទាន់ពេល |
| P7 | **សម្រេចចិត្តទិញឡានថ្មីតាមអារម្មណ៍** | គ្មានទិន្នន័យ ROI/អត្រាប្រើប្រាស់ | វិនិយោគលើប្រភេទដែលមិនចំណេញ |
| P8 | **គ្មានការគ្រប់គ្រងសិទ្ធិ** | អ្នកណាក៏កែសៀវភៅបាន | ហានិភ័យក្លែងបន្លំ |

**លំហូរទិន្នន័យមិនល្អ (poor data flow)៖** ព័ត៌មានតែមួយ (ការកក់) រស់នៅកន្លែង ៣–៤ (សៀវភៅ, វិក្កយបត្រ, Excel, Telegram) ដោយគ្មានកន្លែងណាជា «ប្រភពការពិតតែមួយ» (single source of truth)។
